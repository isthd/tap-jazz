# 実装上の判断と理由（DECISIONS）

仕様書（SPEC.md）から変えた点・解釈した点を記録します。

## ツールチェーン
- **Vite 6 を使用**（最新の Vite 8 ではない）。Vite 8 のネイティブバンドラ（rolldown）がこの Windows 環境のアプリ制御ポリシーでブロックされ、WASM 版も Windows パスを解決できなかったため。Vite 6（rollup + esbuild）は問題なく動作。
- フレームワークなしの Vanilla TypeScript（仕様の推奨どおり）。

## 時間管理（Tone.Transport の代わりに自前の時計）
- 仕様 §2 は Tone.Transport を想定しているが、**小節単位で AudioContext の時刻に直接スケジュールする自前の時計**（`Conductor.tick`、25ms ごと・先読み 0.4 秒）にした。
- 理由：小節内のテンポ変化（熱量による走り、エンディングのリタルダンド、フェルマータ）を拍単位の積分で正確に扱うため。また、タップを「その小節を生成する時点（小節頭の 0.4 秒前）までに届いたもの」で区切ることで、**同じシード＋同じタップ記録で完全に同じ演奏を再現**できる（Node 上のシミュレーションで 3,026 音すべて一致を確認）。
- Tone.js はコンテキスト初期化（`Tone.start`）、ローズのトレモロ／コーラス、クリーンギターのコーラスに使用。

## 音源
- **ピアノ**：Salamander Grand Piano（CC BY 3.0）を 3 半音ごとに `public/samples/piano/` へ同梱（約 1.5MB）。12 秒以内に読めない／12 ゾーン未満の場合は合成ピアノに自動で切り替え。この音源はベロシティレイヤーが 1 段のため、**音量＋ベロシティ連動のローパスフィルタ**で強弱の音色差を出している。
- **その他の楽器はすべてブラウザ内で合成**（仕様 §4.5）：ウッドベース／エレキベース／ギター 3 種は Karplus-Strong、ローズは FM、ヴィブラフォンは加算合成、フルートは正弦波＋息ノイズ、ドラムはノイズと金属的な部分音の重ね合わせ。
  - 理由：無料・再配布可能で品質が揃ったウッドベース、ブラシ、ナイロンギター、エレピの素材をこの環境から確認・取得できなかったため。合成なのでライセンス問題がなく、ダウンロード量もゼロ。
  - 各楽器は起動時に「3 半音ごと × ベロシティ 2 層（＋フィルタで 3 段目）× ラウンドロビン 2 種」をレンダリングしてサンプラーとして鳴らす。サンプル版と同じリバーブ・定位・Humanizer を通る。
  - 合成音と比較できるのはピアノのみ（`?debug=1` の「piano: samples / synth」ボタン）。
- **リバーブ**：小さなクラブを想定したインパルス応答をコードで生成（初期反射＋時間とともに暗くなる残響）。外部 IR を使わないのでライセンス確認不要。
- **アンビエンス**（ざわめき・グラス・拍手・レコードノイズ）もすべて合成。

## 演奏の構成
- **パート参加**：同じ小節に複数の参加が重なった場合は 1 小節に 1 パートずつ、次の小節頭で入る。入る直前の小節で本人がピックアップ（ベースの歩き上がり、ドラムの小さなフィル、ピアノ／ギターの先取りコード）を弾く。
- **セッション開始**：28 タップ到達かつ全パート参加後、次の 4 小節の区切りで 1 曲目のテーマへ。
- **テーマ（ヘッド）を弾くパート**：スウィングとボサノヴァはピアノ（右手でメロディ、左手でシェル）、ネオソウルはギター。サックス等は使わない（仕様 §4.2 で任意）。
- **20 タップ後のタップ楽器**：スウィング＝ヴィブラフォン、ボサノヴァ＝フルート、ネオソウル＝ヴィブラフォン。
- **ソロ回し**：スウィング＝ピアノ→ギター→（45% でベース）、ボサ＝ギター→ピアノ、ネオソウル＝ローズ→ギター→（40% でベース）。75% の確率で 4 小節トレード。
- **ブレイク**：ソロからソロへの受け渡しで 35% の確率。次のソリストが 2 小節ひとりで弾き、そのままソロに入る。
- **ドラマの仕掛け**はクールダウン 16 小節で使いすぎを防止：ドロップダウン（8 小節）、ストップタイム（4 小節）、ダブルタイム（8 小節、ソロの頂点付近）、ペダルポイント（A セクション後半 4 小節、属音）、キメ（セクション末）。
- **拍手**：曲の終わり（大）と、盛り上がったソロの終わり（小）。
- **次の曲**：35% でスタイルが変わり、それ以外はキーが変わる。
- **30 秒タップがない**：次の 8 小節の区切りでエンディング（ターンアラウンドのタグ 3 回 → リタルダンド → フェルマータ → 拍手）、その後はアンビエンスだけ。タップで次の曲がカウントインから始まる。
- **キー変更**：次の小節を新しいキーの ii–V にしてから移る。曲中なら新しいキーでテーマを作り直す。

## 入力
- タップの音は、最寄りのグリッド（スウィングは 3 連、他は 8 分）へ **60% だけ寄せる**（40% のズレを残す）。過去方向には寄せられないので、グリッドが直前にある場合はそのまま鳴らす。
- 45ms 以内の同時タップ（マルチタッチ）は和音として扱い、タップ回数に数えない。
- 長押し（600ms）でもタップの一音は鳴る（押した瞬間に発音するため）。

## オフライン対応
- ピアノのサンプルとフォント（@fontsource）を同梱し、外部への通信をなくした。
- ビルド時に `vite.config.ts` のプラグインが `dist/sw.js` を生成し、ビルドされた全ファイルを最初の訪問時にキャッシュする（キャッシュ優先）。ファイルが変わるとキャッシュ名が変わり、古いキャッシュは削除される。
- サーバーが `Vary` ヘッダーを付けるとキャッシュ照合が外れるため `ignoreVary` を指定。
- 開発サーバー（`npm run dev`）ではサービスワーカーを登録しない。
- ホーム画面に追加できるよう `manifest.webmanifest` とアイコン（SVG）を用意。

## ホスティング
- GitHub Pages（GitHub Actions で `main` へのプッシュごとにビルドして公開）。`base: './'` なのでリポジトリ名のサブパスでもそのまま動く。

## 共有リンク
- `#s=` の後ろに「シード・開始スタイル・テンポ・キー・入力記録（差分ミリ秒）」を JSON → deflate-raw 圧縮 → Base64URL で格納。CompressionStream 非対応ブラウザでは非圧縮。
- 再生中はユーザーのタップを受け付けない（記録どおりに再現するため）。
