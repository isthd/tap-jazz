# Tap Jazz — 仕様書（Claude Code 向け）

> 画面の一箇所をタップしていくだけで、ベース、ドラム、ピアノ、ギター、クラップが一つずつ加わり、気付けば「人間が演奏しているような」お洒落なジャズが鳴っている Web アプリ。

---

## 0. このドキュメントの使い方（Claude Code へ）

- この仕様書をリポジトリ直下に `SPEC.md` として置き、マイルストーン（§11）の順に実装すること。
- **最重要は §6「演奏エンジン（人間らしさ）」**。UI や機能より、ここの品質に最も時間をかける。
- 不明点は勝手に大きく変えず、`docs/DECISIONS.md` に判断と理由を追記して進める。
- 音源のライセンスは必ず確認し、`public/samples/LICENSES.md` に出典・ライセンス・クレジット表記を記録する。

## 1. コンセプト

| 項目 | 内容 |
|---|---|
| 体験 | 画面中央の「一箇所」をタップし続けるだけで、ジャズバンドが少しずつ集まってくる |
| 操作 | タップ = 自分も演奏に参加（一音鳴る）＋ 一定回数ごとに新しいパートが参加 |
| ゴール | 全パートが揃った後、バンドが**感情的で生々しいセッション**を展開し続ける |
| 雰囲気 | 夜のジャズバー。暖色の照明、煙、グラスの音、ざわめき |
| 対象 | スマホ（縦）と PC の両方 |

## 2. 技術スタック

- **Vite + TypeScript**（フレームワークなしの Vanilla TS、または軽量に Svelte。UI が少ないので Vanilla 推奨）
- **Tone.js**：Transport（テンポ・スケジューリング）、`Tone.Sampler`（マルチサンプル再生）、エフェクト
- **Web Audio API**：レイテンシ調整、`MediaStreamAudioDestinationNode` による録音
- **Canvas 2D または PixiJS**：ビジュアル（パーティクル・光の演出）
- 演奏ロジックは **ルールベース＋確率モデル** で自前実装（§6）。外部 AI モデルは使わない前提（任意の実験枠は §6.10）
- ホスティング：静的サイト（Vercel / Netlify / Cloudflare Pages）。サンプル音源は CDN 配信

## 3. 画面とユーザー体験

### 3.1 画面構成

1. **スタート画面**
   - 薄暗いバーのカウンター。中央に小さな光（キャンドルまたはステージのスポットライト）。
   - 「Tap to begin」とだけ表示。最初のタップで AudioContext を有効化（iOS 対策）し、サンプルの読み込みを開始。
   - 読み込み中は店内のざわめき（アンビエンス）だけを先に流して待ち時間を演出にする。
2. **メイン画面**
   - タップ対象は画面中央の光（**タップ領域は画面全体**、光は視覚的な目印）。
   - パートが加わるたびに、奥のステージに演奏者の**シルエット**が一人ずつ浮かび上がる（実在人物・既存キャラクターに似せない、オリジナルの抽象的なシルエット）。
   - タップごとに光の波紋。音量・楽器ごとに色温度の違う光の粒が漂う。
3. **メニュー**（右上の小さなアイコン、普段は控えめ）
   - テンポ、キー、録音、リセット、ミュート

### 3.2 入力

| 端末 | 操作 | 動作 |
|---|---|---|
| スマホ | タップ | 一音演奏＋カウント |
| スマホ | 長押し（600ms 以上） | スタイル切り替え（§5） |
| PC | クリック / スペースキー | タップと同じ |
| PC | 長押し / Shift+スペース | スタイル切り替え |

- Pointer Events で統一。マルチタッチの同時タップは和音として扱ってよい。
- 入力からの発音遅延は 30ms 以内を目標（`Tone.context.lookAhead` を 0.03〜0.05 に調整）。

### 3.3 タップ回数とパート参加（初期値、調整可能な定数にすること）

| 累計タップ | 起きること |
|---|---|
| 1 | タップ楽器（ピアノ or スタイルの主旋律楽器）が一音鳴る。テンポのクリックは鳴らさない |
| 4 | **ベース**参加（最初はルート中心、控えめ） |
| 8 | **ドラム**参加（ブラシ／ハイハットのみから） |
| 12 | **ギター**参加（コンピング） |
| 16 | **クラップ / パーカッション**参加（スタイルに応じて：スウィング＝フィンガースナップ、ボサ＝シェイカー＋リム、ネオソウル＝クラップ） |
| 20 | **ピアノ**がコンピングに回り、タップ楽器は別の音色に移る |
| 28 | フルバンド成立 → **セッションモード**（§6.8）へ |

- パートの参加は即座ではなく、**次の小節頭（または次の4小節フレーズ頭）で入る**。入る直前にドラムの小さなフィルやピックアップを入れて「迎え入れる」感じを出す。
- 参加時に画面にパート名をさりげなくフェード表示（例：「— bass」）。

### 3.4 タップの音（ユーザーの演奏）

- タップの瞬間に鳴らすが、**最も近い8分（スウィング時は3連）グリッドへ弱くクオンタイズ**（完全に吸着させず、ズレを30〜50%残して人間味を保つ）。
- 音高は自動選択：
  - 現在のコードのコードトーン／テンションから選ぶ。強拍はコードトーン優先。
  - 直前の音から近い音へ動く（跳躍は確率的に、跳躍後は逆方向へ順次進行）。
  - 速い連打は上行／下行のランになる。間が空くと音域をリセット。
  - ゆっくりしたタップには和音（2〜3声）を付ける。
- タップのベロシティはタップ間隔から推定（連打は弱め、間を置いた一打は強め）。
- **ユーザーのタップのリズムは「モチーフ」として記録**し、後でソリストがそのリズムを引用・発展させる（§6.6）。ユーザーが「バンドに聴いてもらえている」感覚を作る核心機能。

## 4. 音源（サンプル）

### 4.1 方針

- 録音サンプルのマルチサンプル音源を使用（ベロシティレイヤーとラウンドロビンがあるものを優先）。
- 音質と読み込み速度を両立：各楽器は **3 音ごと程度にサンプリング＋ピッチシフト補間**、OGG/Opus（Safari 用に M4A/AAC フォールバック）。
- **読み込みは段階的に**。最初は最初に鳴る楽器だけ、残りはバックグラウンドで先読み。

### 4.2 必要な楽器

| スタイル | ベース | ドラム | コード | 旋律・ソロ | その他 |
|---|---|---|---|---|---|
| スウィング | ウッドベース（ピチカート） | ブラシ／スティック、ライド、ハット | アコースティックピアノ | ピアノ、ヴィブラフォン、ギター | フィンガースナップ |
| ボサノヴァ | ウッドベース | ブラシ、リム、シェイカー | ナイロンギター、ピアノ | フルート系、ピアノ | シェイカー |
| ネオソウル | エレキベース | タイトなキット、クラップ | エレピ（Rhodes 系） | エレピ、クリーンギター | クラップ |

- 管楽器（サックス等）はサンプルだと不自然になりやすいので**任意**。品質の高い素材が見つかった場合のみ追加。

### 4.3 素材候補（※実装前に必ずライセンスを再確認）

- ピアノ：Salamander Grand Piano（CC-BY 系、要クレジット）
- 打楽器・各種：VCSL（Versilian Community Sample Library、CC0）
- 各種単発音・アンビエンス：Freesound の CC0 素材
- 店内アンビエンス（ざわめき、グラス）：Freesound CC0
- **有料素材は一切使わない**（購入しない）。使えるのは CC0 / CC-BY など無料かつ Web 配信・再配布が許されたものだけ。
- 上記で足りない楽器（ウッドベース、ブラシ、ナイロンギター、エレピ）は、まず無料の素材を探す。見つからない、または品質が足りない場合は**合成で代替**する（§4.5）。

### 4.5 無料素材が足りない場合の合成代替

サンプルとの混在で浮かないよう、同じリバーブ・定位・Humanizer を通すこと。

| 楽器 | 合成方法 |
|---|---|
| ウッドベース（ピチカート） | Karplus-Strong 系の弦モデル＋低域ボディの共鳴フィルタ＋アタックの指ノイズ。音の終わりに短いリリースノイズ |
| ナイロンギター | Karplus-Strong（減衰を速め、高域を柔らかく）＋ボディ共鳴。和音はストロークの時間差（数ms ずつ）で鳴らす |
| エレピ（Rhodes 系） | FM 合成（ベル的なアタック＋柔らかいサステイン）、ベロシティで倍音量を変化、軽いトレモロとコーラス |
| ブラシ | フィルタをかけたノイズ。スウィープ（円を描く音）はノイズの長いエンベロープ、タップは短いバースト |
| クラップ・スナップ | 複数の短いノイズバーストの重ね（微妙な時間差で人数感を出す） |

- 合成音を使った楽器は、開発用パネルでサンプル版と切り替えて聴き比べられるようにする。

### 4.4 サンプラー要件

- ベロシティレイヤー（最低 3 段）、同一音の連続でラウンドロビン。
- ベース・ギターには**奏法バリエーション**（ゴーストノート、スライド、デッドノート）を可能な範囲で用意。
- ピアノはサステインペダル（ノートオフの遅延）を表現。

## 5. スタイルと切り替え

- 3 スタイル：**Swing / Bossa Nova / Neo Soul**。
- 最初のスタイルはランダム（または前回の続き）。
- **長押しで次のスタイルへ**。切り替えは即時ではなく：
  1. 現在のフレーズの終わりまで待つ
  2. ドラムのフィル＋全員でのキメ（ブレイク）
  3. 新スタイルのグルーヴで再開（テンポもスタイルの既定値へ滑らかに移行）
- セッションモード中は、一定の確率で**自然にスタイル変化**してもよい（例：スウィングのソロ後半でダブルタイムフィールに、ボサのテーマで一瞬スウィングに）。

| スタイル | 既定テンポ | 範囲 | 既定キー |
|---|---|---|---|
| Swing | 132 BPM | 90–220 | F |
| Bossa Nova | 128 BPM | 100–150 | D |
| Neo Soul | 84 BPM | 70–100 | E♭ |

## 6. 演奏エンジン（最重要：人間らしさ）

目標：**「プログラムが鳴らしている」ではなく「人間のトリオ〜クインテットが今その場で演奏している」と感じさせる**こと。

### 6.1 アーキテクチャ

```
Conductor（指揮者）
 ├─ Form/Harmony   … 曲の構成、コード進行、リハーモナイズ
 ├─ Intensity      … バンド全体の熱量（0.0–1.0）とその時間変化
 ├─ Players[]      … 各楽器の奏者エージェント
 │    ├─ Bassist / Drummer / Pianist / Guitarist / Percussionist / Soloist
 │    └─ それぞれが「次の1小節（または1拍）」を生成し、Conductor と他奏者の情報を参照
 ├─ Listener       … ユーザーのタップ（密度、リズム、強さ）を解析
 └─ Humanizer      … タイミング・ベロシティ・音長の揺らぎを最終段で付与
```

- 各奏者は**1小節先読み**で生成し、Tone.Transport にスケジュールする。
- 奏者同士は共有の「バンド状態」（現在のコード、熱量、誰がソロ中か、直前のフィル位置など）を読む。
- すべての乱数は **シード付き PRNG**（例：mulberry32）を使い、同じシード＋同じタップ記録で同じ演奏が再現できるようにする（シェア機能で使う、§8）。

### 6.2 構成（フォーム）とハーモニー

- 曲は **オリジナルのコード進行**（既存曲のメロディやタイトルは使わない。一般的な進行パターン＝ii-V-I などはOK）。
- スタイルごとに複数の進行テンプレートを用意し、組み合わせて 32 小節 AABA や 16 小節ブルース風の形式を作る。
- **リハーモナイズ**を確率的に適用（ソロのコーラスごとに少しずつ変える）：
  - 裏コード（トライトーン・サブスティテューション）
  - ii-V の挿入、バックドア ii-V
  - 終止前のターンアラウンドのバリエーション（I-VI-ii-V、iii-VI-ii-V など）
  - ネオソウルでは 9th / 11th / 13th、sus、分数コードを多用
- 1コーラスの流れ：**テーマ → ソロ（複数コーラス） → トレード（4小節交換） → テーマ → エンディング** を繰り返す（§6.8）。

### 6.3 ベーシスト

- **スウィング**：
  - テーマは 2 ビート（2フィール）、ソロに入ったら 4 ビート（ウォーキング）へ。この切り替え自体がドラマになる。
  - ウォーキング規則：拍1＝コードのルート（たまに3度・5度）、拍2・3＝コードトーンかスケール音、拍4＝次のコードのルートへの**半音または全音のアプローチ**。
  - 時々：3連のレイク（装飾）、ゴーストノート、オクターブ跳躍、ペダルポイント。
  - 熱量が高いと音域が上がり、動きが増える。
- **ボサ**：ルート–5度の付点リズム、拍の頭は短め、5度はわずかに長め。
- **ネオソウル**：休符を活かしたシンコペーション、スライド、少しタメた（後ろ気味の）タイミング。

### 6.4 ドラマー

- **スウィングのライド**：「チン・チ・キ・チン」を基本に、**スウィング比をテンポで変える**（遅いと 3:1 寄り、中速 2:1、速いと 1.5:1 寄りのフラット）。
- ハイハットは 2・4 拍。スネアの**コンピング**（会話的な合いの手）は熱量と他奏者の休符に反応して入れる。
- バスドラは「フェザリング」（ごく弱い 4 分）＋時々のアクセント（ボム）。
- **フレーズの区切り（4・8・16・32小節目）でフィル**。フィルの長さと派手さは熱量と構成上の位置で決める。
- 熱量が低い場面はブラシ、高まるとスティックへ持ち替え（テーマ明け、ソロの盛り上がりなど）。
- ネオソウル：スネアはわずかに遅らせ、ハットに強弱の大きなゴースト、クラップはスネアと少しずらして重ねる。

### 6.5 コンピング（ピアノ・ギター）

- **ボイシング**：
  - ピアノは**ルートレス・ボイシング**（3度・7度を中心にテンション付加）、左手はシェル、ボイスリーディングは**各声部の移動量が最小になる**ように選ぶ。
  - 音域の上限・下限を設け、ベースやソロとぶつからないようにする。
  - ギターは 3〜4 声のドロップ 2／シェル。スウィングでは 4 分刻みのコード（オールドスタイル）も選択肢。
- **リズム**：チャールストン、アンティシペーション（次のコードを8分前に先取り）、長い休み。
- **ソリストを邪魔しない**：ソリストが弾いている間は薄く、フレーズの切れ目で応答する（コール＆レスポンス）。
- ピアノとギターが同時にコンピングする時は**どちらかが引く**（交互に主導権）。

### 6.6 ソリスト（即興フレーズ生成）

ここが「感情的な演奏」の中心。

- **モチーフ駆動**：ソロの最初に短いモチーフ（2〜5音）を作るか、**ユーザーのタップのリズムをモチーフとして借りる**。それを
  - そのまま繰り返す
  - 音程を移して繰り返す（シーケンス）
  - リズムをずらす（拍の位置をずらす）
  - 伸ばす／縮める
  
  して発展させる。完全ランダムな音の羅列にしない。
- **ターゲットノート**：強拍にはガイドトーン（3度・7度）や次のコードの重要音を置く。そこに向けて
  - エンクロージャー（上下から挟んで着地）
  - 半音経過音、ビバップ・スケール
  - アルペジオ、テンション（9th、♯11、13th）
  で近づく。
- **呼吸（休符）**：フレーズの長さは 1〜4 小節で可変、フレーズ間に必ず間を作る。人間は息継ぎする。
- **ソロ全体の起承転結**（1ソロ = 2〜4コーラス）：
  1. 序盤：少ない音、中音域、モチーフの提示
  2. 中盤：発展、音域の拡大、リズムの細分化（8分 → 3連 → 16分）
  3. 頂点：最高音域、最大の密度と音量、繰り返しによる煽り
  4. 収束：音数を減らし、次の奏者へ受け渡す
- **アーティキュレーション**：スウィングでは裏拍の8分にアクセント、ゴーストノート（弱く短い音）、フレーズ終わりの音は短く切る／伸ばす を確率で。
- 既存曲のメロディや有名フレーズの引用はしない（オリジナルのみ）。

### 6.7 Humanizer（最終段の揺らぎ）

全パートの発音に最後にかける。**ランダムではなく、方向性のある揺らぎ**にすること。

| 要素 | 内容 |
|---|---|
| タイミングの癖 | 奏者ごとに固定の傾向：ベースとライドは**わずかに前（on top）**、ピアノ・ソロは**少し後ろ（laid back, +10〜30ms）**、ネオソウルは全体的に後ろ |
| タイミングの揺らぎ | 上記の傾向の周りに小さなばらつき（±5〜15ms、正規分布） |
| ベロシティ | 拍の位置（スウィングでは 2・4 拍と裏拍が強め）、フレーズ内の山なり（クレッシェンド→デクレッシェンド）、熱量 |
| 音長 | レガート／スタッカートを奏者とフレーズで変える |
| テンポ | 熱量が高い場面でわずかに走る（最大 +1〜2%）、エンディングでリタルダンド |
| ラウンドロビン | 同じ音でも毎回違うサンプル／わずかなピッチ・フィルタ差 |

### 6.8 セッションモード（全パート参加後）

全パートが揃ったら、バンドは**勝手に「1曲」を演奏し続ける**。ユーザーのタップは「客席からの煽り」兼「飛び入り演奏」になる。

**流れ**（ループしながら毎回違う展開）：

1. **テーマ（Head）**：全員でテーマ。テーマのメロディもオリジナル生成し、2回目以降は同じテーマを崩して弾く（ジャズらしさ）。
2. **ソロ回し**：ピアノ → ギター → （ベースソロ：伴奏が極端に薄くなる） の順など、スタイルごとに変える。
3. **トレード**：ソリストとドラムが4小節ずつ交換。
4. **テーマに戻る**
5. **エンディング**：ターンアラウンドの繰り返し → リタルダンド → 最後の和音をフェルマータ → シンバルの余韻 →（少しの拍手とざわめき）→ 次の曲のカウントイン（スタイルやキーが変わる）

**ドラマの仕掛け**（確率で発生、使いすぎない）：

- **ブレイク / ストップタイム**：全員が止まり、ソリストだけ 2 小節弾く
- **キメ**：全員が同じリズムでコードを叩く
- **ドロップダウン**：ベースとブラシだけになって静まり、そこから全員で戻る
- **ペダルポイント**：ベースが同じ音を保ち、上でコードが動いて緊張を作る
- **ダブルタイム・フィール**：ソロの頂点で一時的に倍の細かさに

**熱量（Intensity）の制御**：

- 基本はフォーム上の位置で決まる「理想の熱量カーブ」に従う（テーマ中くらい → ソロで上昇 → 頂点 → 収束）。
- ユーザーの**タップ頻度が高い**と熱量が上がる（煽り）、**しばらくタップがない**と下がる。
- 30 秒以上タップがない → バンドは静かに演奏を続け、やがてエンディングで曲を締めて、アンビエンスだけになる。再びタップすると次の曲が始まる。

### 6.9 ミックスと空間

- 古典的なジャズ録音を意識した**定位**：ドラムはやや左、ベース中央、ピアノやや右、ギター左寄り（スタイルで調整）。
- 小さなクラブの**コンボリューション・リバーブ**（短め、IR はライセンス確認済みのもの）。
- バス全体に軽いコンプとテープ風サチュレーション、ローファイすぎない程度のハイカット。
- **店内アンビエンス**（ざわめき、グラス、時々の小さな拍手）を常時うっすら流す。ソロの頂点やエンディング後に拍手・歓声を小さく足す。
- ネオソウルのみ、アナログレコード風のノイズを任意で。

### 6.10 （任意・実験）機械学習モデル

- 主実装はルールベース。品質がそれで頭打ちになった場合のみ、ブラウザで動く旋律生成モデル（例：Magenta.js 系）をソロ生成の候補として試すブランチを切ってよい。ただし保守状況と読み込みサイズを確認し、本流には入れない判断も可。

## 7. ビジュアル（夜のジャズバー）

- 色：深いネイビー〜黒の背景、アンバー・琥珀色の照明、所々に赤いネオンの差し色。
- タイポ：アールデコ調のディスプレイ書体（Google Fonts からライセンス確認済みのもの）＋読みやすい本文書体。
- 演出：
  - タップ位置から光の波紋、音量に応じて大きさ・明るさが変化
  - 参加中の楽器ごとにステージ上のシルエットが浮かび、演奏している瞬間に照明が当たる
  - ソロ中の奏者にスポットライト
  - 煙（ゆっくり動く半透明のノイズ）、ろうそくの揺らぎ
- 画面は音楽の邪魔をしない：60fps 目標、低性能端末では演出を自動で軽くする。
- `prefers-reduced-motion` に対応。

## 8. 追加機能

### 8.1 録音・保存・シェア

- メニューの録音ボタンで、マスター出力を `MediaRecorder` で録音（`MediaStreamAudioDestinationNode` 経由）。
- 停止後：
  - **音声ファイルとして保存**（ブラウザがサポートする形式。可能なら WAV へ変換してダウンロード）
  - **Web Share API**（ファイル共有対応端末）で共有、非対応ならダウンロード
- **リンクで共有**：シード値＋タップのタイムスタンプ記録＋スタイル・テンポ・キーを URL（短縮した JSON の Base64 等）にして、開いた人のブラウザで同じセッションを再生できるようにする。

### 8.2 テンポ・キー変更

- メニュー内のスライダー（テンポ）とセレクタ（12 キー）。
- 変更は次の小節頭で反映。キー変更はスムーズに聞こえるよう、ドミナントを経由した転調として演奏する。
- スタイルごとのテンポ範囲（§5）を超えない。

### 8.3 リセット・ミュート

- リセット：エンディングを弾いてから初期状態へ（ぶつ切りにしない）。
- ミュート：アンビエンス含め全停止。

## 9. 非機能要件

- 初回表示 2 秒以内（音源は段階読み込み）。全音源の合計は 1 スタイルあたり 15MB 以内を目安。
- iOS Safari、Android Chrome、デスクトップ Chrome / Safari / Firefox の最新版。
- iOS のマナーモードで音が出ない問題への案内を表示。
- バックグラウンドタブ化で一時停止、復帰で再開。
- 長時間（30分以上）の連続演奏でメモリリーク・音切れがないこと。

## 12. 品質チェック（聴いて確認する項目）

開発中、各マイルストーンで以下を確認する。開発用に `?debug=1` で「熱量・現在コード・各奏者の状態」を表示するパネルと、**特定のシードで同じ演奏を何度も聴ける機能**を用意する。

- [ ] 1分聴いて「機械っぽい」と感じる瞬間がないか（同じパターンの繰り返し、全員が同時に同じことをする等）
- [ ] ベースが次のコードに自然に「歩いて」向かっているか
- [ ] ソロに起承転結があり、休符（呼吸）があるか
- [ ] コンピングがソロとぶつかっていないか
- [ ] フィルやブレイクがフレーズの区切りにあり、使われすぎていないか
- [ ] タップした音がバンドの中で浮かず、ハーモニーに合っているか
- [ ] 自分のタップのリズムがソロで返ってきたと感じられるか
- [ ] スタイル切り替えが「同じバンドが曲を変えた」ように聞こえるか
- [ ] 5分以上聴いても飽きない変化があるか
